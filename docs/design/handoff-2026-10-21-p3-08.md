## 1. 本项问题

### 1.1 `isPathSafe` 的新文件 fallback

`src/lib/path-safety.ts:18`

- 已存在路径：`realpathSync(resolve(workDir, filePath))`，能识别 symlink。
- 不存在路径：catch 后只做 `resolve + startsWith`。
- 因此新文件的**父目录若是 symlink**，`resolve` 仍认为在 workDir 内，但真实父目录可能指向 workDir 外。
- 典型触发：workspace 内存在 `link -> C:\outside`，请求写 `link/new.txt`；目标文件不存在，进入 fallback，随后 `mkdir`/`writeFile` 跟随 symlink 写到外部。

### 1.2 files accept

`src/app/api/sessions/[id]/files/accept/route.ts`

- `baseDir = join(process.cwd(), 'workspaces', sessionId)`。
- `isPathSafe(normalizedPath, baseDir)` 在 `mkdir(dirname(fullPath))` 之前调用。
- 已有 `target=project` 拒绝、敏感路径拒绝、UUID/session 校验；不要回退。
- 新文件父目录 symlink 是当前缺口。
- `mkdir(dirname(fullPath), { recursive: true })` 会跟随已有 symlink。

### 1.3 files download

`src/app/api/sessions/[id]/files/[filename]/route.ts`

- `filename` 只挡 `..` / `/` / `\`，是单段。
- 仍用 `join(process.cwd(), 'workspaces', sessionId, filename)` + `readFile`。
- 如果 workspace 内 `filename` 是指向 workDir 外的 symlink，单段检查通过，`readFile` 会读取外部文件。
- 当前没有 `isPathSafe`/`realpath` 校验。

## 2. 推荐最小修法

### 2.1 修 `isPathSafe` 的 fallback

对不存在的目标：

1. `resolvedWorkDir = realpathSync(workDir)`（已有）。
2. `target = resolve(resolvedWorkDir, filePath)`。
3. 从 `target` 开始向上找**最近存在的祖先目录**，对祖先做 `realpathSync`。
4. 祖先真实路径必须在 `realWorkDir` 内；否则拒绝。
5. 同时保留 `resolve + startsWith` 的 `..` 防护。
6. 若没有任何存在的祖先（异常/根不可读），fail-closed 或保留原 fallback；不要把“无法证明”当成安全。
7. `target` 自身存在时仍优先 `realpathSync(target)`。

注意：

- 不要只检查 `dirname(target)` 一次；父目录可能不存在，需要向上找最近存在的祖先。
- 不要用字符串 `startsWith(workDir)` 不带 `sep`，已有 `sep` 逻辑保留。
- Windows 大小写/分隔符按 Node `resolve`/`realpath` 语义处理，不要手写字符串替换绕过。

### 2.2 accept

- 保留现有 UUID / session / sensitive / `target=project` 检查。
- `isPathSafe` 修好后，写入前仍需验证父目录真实路径；建议在 `mkdir` 后、`writeFile` 前再 `realpathSync(dirname(fullPath))` 并断言在 `baseDir` 内。
- 如果 `mkdir` 后父目录真实路径逃逸，返回 400/403，不写文件。
- 注意 `mkdir` 可能已经创建了 workspace 内目录；失败时不要留下越界文件。

### 2.3 download

- 用 `isPathSafe(filename, baseDir)` 或在 `readFile` 前 `realpathSync(filePath)` 并检查在 `baseDir` 内。
- 目标不存在时按 404；目标真实路径越界时返回 400/403。
- 保留 `Content-Disposition: attachment` 和现有 filename 单段限制。
- 不要因为修 symlink 而放开 `filename` 的单段限制。
